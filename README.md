# Движ-Патруль

Мобильное веб-приложение городского фото-квеста. Команды получают
задания, снимают фотографии, отправляют их на проверку; простое
засчитывается автоматически, спорное решает организатор. Баллы и
рейтинг считаются на сервере.

Сделано под конкретное мероприятие — **Leipzig, 15.08.2026** — но
следующий квест заводится через админку, без правки кода.

## Что умеет

**Участник.** Создаёт команду или входит по шестизначному коду —
без email и пароля. Видит задания, снимает, отправляет и **сразу
идёт дальше**, не дожидаясь проверки. Следит за баллами и местом.
На карте видит границы игрового поля и задания с привязкой к
месту.

**Организатор.** Заводит мероприятие, импортирует 30–50 заданий
файлом, запускает и останавливает квест, разбирает **только
спорные** фотографии, меняет баллы, управляет рейтингом,
выгружает результаты.

**Приложение.** Сжимает фотографии в браузере и снимает с них
метаданные, хранит снимки в приватном бакете, проверяет часть
заданий через Gemini, ведёт очередь проверок в самой базе,
переживает обрывы связи и **работает полностью без AI**.

## Стек

Next.js 16 · React 19 · TypeScript strict · Tailwind CSS v4 ·
Supabase (Postgres, Auth, Storage) · Gemini API (опционально) ·
Vercel

## Быстрый старт

```bash
npm install
cp .env.example .env.local          # заполнить
npm run dev
```

Полная установка с нуля — [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

### Требования

- Node.js 20.9+
- проект Supabase
- ключ Gemini — **необязательно**

### Supabase

Создайте **отдельный** проект и накатите миграции по порядку:

```
supabase/migrations/0001_schema.sql
supabase/migrations/0002_functions.sql
supabase/migrations/0003_views.sql
supabase/migrations/0004_rls.sql
supabase/migrations/0005_storage.sql
supabase/migrations/0006_seed_event.sql
supabase/migrations/0007_play_area.sql
```

Через SQL Editor или `npx supabase db push`.

Файл `supabase/local/00-supabase-shim.sql` на Supabase **не
применяется** — это заглушки для локального Postgres.

### Администратор

```bash
node scripts/create-admin.mjs you@example.com "надёжный-пароль"
```

Вход: `/admin/login`

### Задания

Двенадцать демонстрационных приезжают с миграцией. Реальные
загружаются через `/admin/import`; образец на 30 заданий —
`data/tasks.example.json`.

## Переменные окружения

Полный список с пояснениями — в `.env.example`.

Обязательные:

```bash
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=      # только сервер
SESSION_SECRET=                 # openssl rand -base64 48
```

Без Gemini приложение работает полностью: все фотографии идут в
ручную проверку. Это штатный режим, а не аварийный.

## Решения, которые стоит знать

**Баллы — журнал, а не счётчик.** `teams.total_score` не
существует. Сумма считается по `score_transactions`. Отмена не
удаляет строку, а добавляет обратную. Через месяц можно
объяснить любую цифру.

**Лимиты держит база, а не код.** Регистрация одиннадцатой
команды и пятого участника невозможны на уровне advisory-локов и
уникальных индексов. Проверено двадцатью параллельными запросами.

**AI не может отклонить.** Принять или отдать человеку. Любой
сбой, таймаут или непонятный ответ — ручная проверка, а не отказ
участнику.

**Очередь в Postgres.** `FOR UPDATE SKIP LOCKED` вместо Redis: на
500 задач внешний брокер — лишний сервис, который может отказать
посреди мероприятия.

**Участники не пишут в базу.** У них нет ни одной политики
INSERT/UPDATE/DELETE. Запись идёт через сервер, который знает
команду из httpOnly cookie.

**Метаданные фотографий не покидают телефон.** Перерисовка через
canvas при сжатии отбрасывает EXIF целиком, включая координаты
съёмки.

## Отступления от технического задания

Три, все сознательные и описаны в документации:

**Палитра.** `DESIGN (1).md` описывает строгий монохром и прямо
запрещает красный постера в интерфейсе. Этот запрет —
формулировка самого документа, а не пожелание заказчика:
заказчик хотел ровно обратного, чтобы сайт был максимально похож
на постер. Поэтому цвета сняты с постера пипеткой и посчитаны по
долям площади. Плоскость, единый радиус и отсутствие теней от
исходной системы сохранены; красный остаётся акцентом на один-два
элемента экрана, а не заливкой всего подряд.

**Шрифт.** ТЗ называет Fraunces как запасной вариант. В нём нет
кириллицы, а весь интерфейс русскоязычный. Взята Literata для
текста и Oswald для плакатных заголовков — узкий гротеск в
капители, как «LEIPZIG» на постере.
См. [DESIGN_SYSTEM.md](docs/DESIGN_SYSTEM.md).

**Realtime.** Вместо клиентской подписки Supabase Realtime сделан
адаптивный опрос: обновление раз в 20 секунд, только пока есть
отправки в работе, плюс при возврате на вкладку и восстановлении
связи. Подписка потребовала бы выдать браузеру токен с правом
читать таблицу отправок напрямую.
См. [ARCHITECTURE.md](docs/ARCHITECTURE.md#обновление-статусов--опрос-а-не-supabase-realtime).

## Постер

Утверждённый макет лежит в
`public/assets/dvizh-patrol-poster.jpg`. Плитки коллажа на
главной — его фрагменты, а не сгенерированные картинки.

Перегенерировать после замены постера:

```bash
node -e "
const sharp = require('sharp');
const src = 'public/assets/dvizh-patrol-poster.jpg';
// Только фотографические участки постера: типографика в плитки
// попадать не должна, иначе на главной задвоятся «15.08» и
// «ДВИЖ-ПАТРУЛЬ». Фотография на постере занимает y ≈ 1020…1300.
const tiles = [
  { name: 'tile-tower',  left: 508, top: 600,  width: 118, height: 126 },
  { name: 'tile-roofs',  left: 250, top: 1045, width: 300, height: 240 },
  { name: 'tile-facade', left: 60,  top: 1110, width: 300, height: 180 },
  { name: 'tile-arcade', left: 930, top: 1085, width: 190, height: 195 },
  { name: 'tile-square', left: 780, top: 1050, width: 280, height: 235 },
  { name: 'tile-plaza',  left: 620, top: 1140, width: 230, height: 150 },
];
(async () => {
  for (const t of tiles) {
    await sharp(src)
      .extract(t)
      .resize(320, 320, { fit: 'cover' })
      .webp({ quality: 82 })
      .toFile('public/assets/' + t.name + '.webp');
  }
  // Полоса города для героя главной — та же фотография во всю ширину.
  await sharp(src)
    .extract({ left: 0, top: 1020, width: 1122, height: 295 })
    .resize(1600)
    .webp({ quality: 88 })
    .toFile('public/assets/hero-city.webp');

  // Картинка превью ссылки. Обрезана до нижней строки постера:
  // «20+ фото-заданий» разъедется с реальным числом заданий.
  const card = await sharp(src)
    .extract({ left: 0, top: 818, width: 1122, height: 557 })
    .toBuffer();
  await sharp(card)
    .resize(1200, 630, { fit: 'contain', background: '#f0dbc9' })
    .jpeg({ quality: 90 })
    .toFile('public/assets/og-image.jpg');
})();
"
```

## Диагностика

**«Некорректная конфигурация окружения».** Не заполнен
`.env.local`. Сообщение перечисляет недостающие переменные.

**Регистрация отвечает «мест нет», хотя команд мало.** Проверьте
`max_teams` в `/admin/event` и отменённые команды в
`/admin/teams`.

**Задания не видны участникам.** Они скрыты до старта намеренно.
Статус мероприятия должен быть «Идёт».

**Фотографии не проверяются.** Без `GEMINI_API_KEY` они уходят в
ручную проверку — это ожидаемо. Иначе смотрите «Ошибки проверки»
и кнопку «Обработать зависшие».

**Отправки застряли в «Проверяется».** `/admin` → «Повторно
обработать зависшие». Повтор не начисляет баллы дважды.

**«Трамвай» и «трамвай» зарегистрировались как разные команды.**
Локаль базы не юникодная. На Supabase такого не бывает; при
своём Postgres — `initdb --locale=C.UTF-8`.

Остальное — [INCIDENT_PLAN.md](docs/INCIDENT_PLAN.md).
