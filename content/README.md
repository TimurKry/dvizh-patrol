# Материалы мероприятия

Всё, что готовит организатор: фотографии, тексты, данные. Складывайте
в папку по номеру — в каждой лежит `README.md` с требованиями именно
к этому материалу.

## Что нужно прислать

| № | Материал | Сколько | Формат и разрешение |
|---|---|---|---|
| 01 | Фотографии Лейпцига для героя | 8–12 | JPG, вертикальные 4:5, от 2400×3000 |
| 02 | Референсы для фото-заданий | 6–9 | JPG/PNG, горизонтальные 4:3, от 2400×1800 |
| 03 | Примеры выполненных заданий | 4–6 | JPG, 4:3, от 1600×1200 |
| 04 | Рисунки и наброски для активов | 3–5 | PNG с прозрачностью или SVG, от 2000×2000 |
| 05 | Фотографии BBQ-локации | 2–4 | JPG, 3:2, от 2400×1600 |
| 06 | Граница игрового поля | 1 | GeoJSON/KML, либо PNG 3000×3000 |
| 07 | Примеры заданий | 6–12 | Текст, CSV, XLSX или JSON |
| 08 | Примерные команды | 4–6 | Название, цвет, состав — можно вымышленные |
| 09 | Ссылки Telegram | все | Канал, чат, менеджер |
| 10 | Информация о BBQ | 1 набор | Время, адрес, точка карты, цена для гостей |
| 11 | Игровое расписание | 1 набор | Сбор, старт, финиш, BBQ, результаты |

## Как класть

Копируйте файлы прямо в нужную папку, потом одним разом:

```bash
git add content
git commit -m "Материалы мероприятия"
git push
```

**Не по одному файлу через веб-интерфейс GitHub** — так каждая
картинка становится отдельным коммитом, а промахнуться папкой проще
простого.

## Правила, общие для всего

**Присылайте оригиналы.** JPG или PNG в том качестве, в каком снято.
Сжатие, `webp` и ресайз делает приложение; пересжатый файл обратно не
восстанавливается.

**Соблюдайте пропорции из таблицы.** Кадр другой формы придётся
обрезать, и обрежется ровно то, что вы считали главным.

**Имена по смыслу.** `hero-markt-01.jpg`, `task-07-taksa.jpg` —
а не `photo_3_2026-08-10_02-28-28.jpg`. Через неделю сами не
вспомните, что это.

**Метаданные не чистите** — снимаются при обработке. У фотографий
участников это происходит автоматически прямо в браузере, включая
координаты съёмки.

**Согласие на съёмку.** Если на кадре узнаваемые люди — спросите
разрешение до публикации. То же правило записано в правилах для
участников.

## Эта папка не источник для приложения

Файлы отсюда **не видны участникам сами по себе**. Это рабочий склад:
материалы лежат под версионным контролем, и отсюда их удобно
передавать в работу.

В приложение они попадают по-разному:

| Материал | Как доезжает до участника |
|---|---|
| Референсы заданий (02) | загружаются через `/admin/tasks/<id>` в приватный бакет, отдаются по подписанной ссылке |
| Задания (07) | импортом файла через `/admin/import` |
| Граница поля (06) | вносится в `/admin/event` |
| BBQ, расписание, Telegram (09–11) | вставляются в код страниц |
| Фотографии для героя и примеров (01, 03, 04, 05) | обрабатываются и кладутся в `public/assets/` |

> **Почему не сразу в `public/`.** Всё, что лежит в `public/`,
> доступно по прямой ссылке любому в интернете. Референсы заданий там
> означали бы, что содержание квеста можно посмотреть заранее, просто
> угадав имя файла. Поэтому они хранятся в приватном бакете, а не в
> коде.

Репозиторий приватный, так что и здесь материалы посторонним не
видны.
