# Руководство организатора

## Вход

`/admin/login`, email и пароль. Учётная запись создаётся
скриптом — см. [DEPLOYMENT.md](./DEPLOYMENT.md).

Наличие аккаунта Supabase само по себе прав не даёт: нужна
строка в `admin_users`. Внешнего ключа между ней и Auth нет, так
что удалить пользователя и остаться с осиротевшей строкой — самый
частый способ потерять вход.

Не пускает? Разбор по шагам, вместе с готовыми запросами, —
в [OWNER_SETUP.md](./OWNER_SETUP.md), раздел «Если не пускает в
админку». Восстановления пароля по почте в приложении нет: пароль
задаётся напрямую.

## Состояния мероприятия

```
Черновик → Регистрация → Идёт ⇄ Пауза → Завершён → Архив
```

| Статус      | Регистрация | Задания | Отправки |
| ----------- | :---------: | :-----: | :------: |
| Черновик    |   закрыта   | скрыты  |   нет    |
| Регистрация |   открыта   | скрыты  |   нет    |
| Идёт        |   закрыта   |  видны  |    да    |
| Пауза       |   закрыта   |  видны  |   нет    |
| Завершён    |   закрыта   |  видны  |   нет    |
| Архив       |   закрыта   |  видны  |   нет    |

Переходы делаются кнопками на сводке или в разделе
«Мероприятие». Запуск квеста автоматически закрывает регистрацию:
добирать команды на ходу — почти всегда ошибка.

**Обратно тоже можно.** Из «Регистрации» и из «Завершён» есть
кнопка «Вернуть в черновик» — оттуда набор открывается заново. Это
нужно после обкатки: прогнали квест целиком, чтобы проверить, и
вернулись к подготовке настоящего. Данные при этом остаются на
месте — команды, отправки и баллы; скрываются только задания и
результаты. Чистят их отдельно, вручную.

Необратим только архив, и попасть туда можно лишь из «Завершён».

**Задания скрыты до старта намеренно.** Иначе команды изучат
список заранее и распланируют маршрут, что убивает смысл.

## Подготовка

### За неделю

1. **Мероприятие.** Дата, время, часовой пояс, цена, лимиты.
2. **Задания.** Импортируйте 30–50 через `/admin/import`.
   Формат — в [TASK_IMPORT_FORMAT.md](./TASK_IMPORT_FORMAT.md).
3. **Критерии.** Пройдитесь по заданиям с режимом «Автоматическая
   проверка»: критерии должны быть проверяемы **по фотографии**.
   «Команда проявила смекалку» проверить нельзя.
4. **Репетиция.** Заведите тестовую команду, запустите квест,
   отправьте фотографию, примите её, убедитесь, что баллы
   начислились. Потом отмените команду.

### За день

Откройте регистрацию, разошлите ссылку. Отмечайте оплату по мере
поступления: `/admin/teams/<id>` → «Подтвердить оплату».

### За час

Закройте регистрацию, проверьте составы. Откройте админку на
ноутбуке — с телефона разбирать очередь неудобно.

## Во время квеста

### Запуск

Сводка → «Запустить квест». Задания становятся видны всем
командам немедленно.

### Очередь проверки

`/admin/submissions`, вкладка «Ручная проверка» открыта по
умолчанию — это то, что ждёт вашего решения.

Карточка проверки показывает:

- фотографию команды крупно;
- эталон задания, если он есть;
- условие и критерии;
- разбор автоматической проверки по каждому критерию;
- предполагаемый дубликат рядом, если он найден;
- геопозицию, если задание её требует;
- номер попытки.

Решения:

| Кнопка          | Что делает                                              |
| --------------- | ------------------------------------------------------- |
| Принять         | Засчитывает, начисляет баллы (можно изменить)           |
| Отклонить       | Не засчитывает. Если было принято — снимает баллы       |
| Переснять       | Отклоняет с пояснением, попытка остаётся использованной |
| Проверить снова | Возвращает на автоматическую проверку                   |

Комментарий виден участникам. Не ленитесь его писать: «на
фотографии не видно знака» экономит вам же спор на BBQ.

**После решения автоматически открывается следующая фотография.**

### Похожие фотографии

Если система нашла похожий снимок, вы увидите оба рядом и
процент сходства.

Совпадение **не отклоняет отправку** — решение за вами.
Перцептивный хэш ловит и честные совпадения: две команды сняли
один памятник с одной точки.

### Ручные начисления

`/admin/teams/<id>` → бонус, штраф или корректировка. Причина
обязательна — она попадёт в журнал и в экспорт.

Знак выводится из типа: штраф всегда отрицательный.

### Рейтинг

`/admin/leaderboard`. Заморозка за час до финиша сохраняет
интригу: участники видят зафиксированную таблицу, вы — реальную.

## После квеста

1. **Завершить квест** — отправки закрываются.
2. Досмотреть очередь.
3. Разморозить рейтинг.
4. Объявить результаты.
5. Выгрузить CSV из `/admin/export`.

### Экспорт

| Файл              | Содержимое                                        |
| ----------------- | ------------------------------------------------- |
| Команды           | Названия, коды, капитаны, контакты, баллы         |
| Участники         | Состав всех команд                                |
| Задания           | В формате импорта — переносится в следующий квест |
| Отправки          | Все фотографии со статусами и путями в хранилище  |
| Рейтинг           | Итоговая таблица                                  |
| Журнал начислений | Каждое изменение баллов                           |
| Согласия          | Кто разрешил публикацию фотографий                |

Файлы в UTF-8 с BOM — открываются в Excel без плясок с
кодировкой.

**Ссылок на фотографии в CSV нет** намеренно: подписанная ссылка
живёт час, а таблица остаётся надолго. Вместо них — путь в
хранилище.

### Выгрузка фотографий

```bash
supabase storage download \
  --recursive ss:///submission-images/events/<eventId> \
  ./фотографии-квеста
```

Около 400 МБ на 500 фотографий.

### Публикация

**Проверьте файл согласий перед публикацией.** Согласие на
участие — не то же самое, что согласие на соцсети. Публиковать
можно только фотографии команд, отметивших второй флажок.

## Хранение фотографий

`/admin/settings` показывает, сколько файлов просрочено по сроку
хранения, и позволяет их удалить.

Удаляются **файлы**, записи об отправках остаются: журнал
начислений и рейтинг не должны разъезжаться из-за уборки.

Срок хранения задаётся в настройках мероприятия и виден
участникам на странице о конфиденциальности.

## Журнал действий

`/admin/audit` — все изменения, влияющие на результат: смена
статуса, правки заданий, начисления, решения по фотографиям,
импорт.

Записи не удаляются. Через месяц по ним можно восстановить,
почему результат получился именно таким.

## Следующее мероприятие

Код менять не нужно:

1. Выгрузите задания текущего квеста.
2. Создайте новое мероприятие в базе (новый `slug`).
3. Импортируйте задания, поправьте под новый город.
4. Откройте регистрацию.

Старое мероприятие отправьте в архив.
