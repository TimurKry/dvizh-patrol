# Автоматическая проверка

## Главное правило

**Модель может принять фотографию или отдать её человеку.
Отклонить — никогда.**

Из этого следует всё остальное:

- таймаут → ручная проверка;
- сбой сети → повтор, затем ручная проверка;
- неразобранный ответ → ручная проверка;
- уверенность ниже порога → ручная проверка;
- невыполненный критерий при вердикте «принять» → ручная проверка;
- ключ не задан → ручная проверка.

Участник никогда не получает отказ от машины. Отказать может
только организатор.

## Приложение без Gemini

Работает полностью. Если `GEMINI_API_KEY` не задан или
`ai_validation_enabled = false`:

| Режим задания | Что происходит |
|---|---|
| `auto` | Принимается сразу, баллы начисляются |
| `manual` | Уходит организатору |
| `ai` | Уходит организатору с причиной `ai_unavailable` |

Участник видит «Фотография ожидает ручной проверки». Технических
подробностей ему не показывают: он всё равно ничего с ними не
сделает.

Мероприятие можно провести целиком вручную. Это штатный режим,
а не аварийный.

## Что уходит в модель

Отправляется:

- название и описание задания;
- список критериев;
- минимальное число людей в кадре;
- фотография команды;
- эталонное изображение, если оно есть.

**Не отправляется:** имена участников, название команды,
контакты, идентификаторы, геопозиция, любые метаданные.

Модели незачем знать, кто на фотографии.

## Запреты в системной инструкции

Прямо запрещено:

- опознавать людей и сравнивать лица;
- называть или предполагать имена;
- определять возраст, пол, национальность, происхождение,
  вероисповедание;
- делать выводы о здоровье и состоянии;
- оценивать внешность, одежду, телосложение;
- рассуждать о любых чувствительных характеристиках.

Людей модель описывает обезличенно: «человек», «двое людей».

Художественное качество и оригинальность не оцениваются —
только фактическое соответствие условиям.

## Формат ответа

Используется structured output: модель обязана вернуть JSON
заданной формы.

```json
{
  "decision": "accept",
  "confidence": 0.93,
  "checks": [
    {
      "criterion": "Виден треугольный дорожный знак",
      "passed": true,
      "confidence": 0.97,
      "comment": "Знак в левой части кадра"
    }
  ],
  "reason": "Знак и двое участников хорошо видны."
}
```

Ответ дополнительно проверяется схемой Zod. Любое расхождение —
`manual_review`.

## Принятие решения

`decide(result, threshold)` в `lib/ai/gemini.ts`:

```
decision ≠ 'accept'              → manual_review (ai_low_confidence)
confidence < порог мероприятия   → manual_review (ai_low_confidence)
есть невыполненный критерий      → manual_review (criterion_failed)
иначе                            → accept
```

Третья строка разбирает противоречие: модель сказала «принять»,
но отметила критерий как невыполненный. Разрешается в пользу
человека.

Порог берётся из `events.ai_accept_threshold`, а не из
переменной окружения: организатор меняет его прямо во время
квеста, если видит, что проверка ошибается. По умолчанию 0.88.

## Настройки

```bash
GEMINI_API_KEY=            # пусто — всё вручную
GEMINI_MODEL=gemini-2.5-flash
AI_VALIDATION_ENABLED=true
AI_ACCEPT_THRESHOLD=0.88   # значение по умолчанию для новых мероприятий
AI_REQUEST_TIMEOUT_MS=20000
AI_MAX_CONCURRENCY=4       # 1–6
AI_STALE_CHECK_MINUTES=5
AI_MAX_ATTEMPTS=2
```

Ключ используется только на сервере. `lib/env.ts` помечен
`server-only`, префикса `NEXT_PUBLIC_` у ключа нет.

## Обработка ошибок

| Ситуация | Действие |
|---|---|
| HTTP 429 или 5xx | Повтор через 20 с, до `AI_MAX_ATTEMPTS` |
| Таймаут | То же |
| HTTP 4xx | Без повтора → ручная проверка |
| Пустой ответ, сработал фильтр | Ручная проверка |
| JSON не разобрался | Ручная проверка |
| Ответ не прошёл Zod | Ручная проверка |
| Попытки исчерпаны | Ручная проверка, причина `ai_error` |

Все ошибки видны организатору на вкладке «Ошибки проверки».

## Пример

**Задание.** «Найдите треугольный знак дорожных работ. Минимум
два участника должны повторить позу рабочего».

**Критерии:**
1. На фотографии виден треугольный знак дорожных работ.
2. Видно минимум два участника.
3. Участники изображают копание или работу.

**Ответ модели:**

```json
{
  "decision": "manual_review",
  "confidence": 0.62,
  "checks": [
    {"criterion": "Виден треугольный знак", "passed": true,
     "confidence": 0.95, "comment": "Знак в кадре справа"},
    {"criterion": "Видно минимум два участника", "passed": true,
     "confidence": 0.90, "comment": "В кадре два человека"},
    {"criterion": "Участники изображают копание", "passed": false,
     "confidence": 0.40, "comment": "Поза читается неоднозначно"}
  ],
  "reason": "Знак и два человека видны, но поза не похожа на копание."
}
```

Результат: `manual_review`. Организатор откроет очередь, увидит
фотографию, эталон, разбор по критериям и решит сам.

## Стоимость

При 500 фотографиях и `gemini-2.5-flash` расход на порядок ниже
евро за мероприятие. Сжатие до 1600px по длинной стороне снижает
и трафик, и число токенов на изображение.

Если квота кончилась — см. [INCIDENT_PLAN.md](./INCIDENT_PLAN.md):
проверка выключается одним переключателем, квест продолжается.
