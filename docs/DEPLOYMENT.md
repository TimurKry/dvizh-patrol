# Развёртывание

Полный путь от пустого проекта до работающего квеста. Занимает
около получаса.

## Что понадобится

- Node.js 20.9 или новее;
- аккаунт Supabase (бесплатного тарифа достаточно);
- аккаунт Vercel;
- ключ Gemini API — **необязательно**.

## 1. Проект Supabase

Создайте **отдельный** проект. Не накатывайте миграции в базу, где
уже что-то есть: имена `tasks`, `events`, `submissions`
достаточно общие, чтобы столкнуться.

Регион выбирайте ближайший к городу квеста: для Лейпцига это
`eu-central-1` (Франкфурт).

> **Локаль базы.** Уникальный индекс по имени команды опирается на
> `lower()`, которая понимает кириллицу только в юникодной
> локали. У Supabase она корректная по умолчанию. Если поднимаете
> Postgres сами — `initdb --locale=C.UTF-8`, иначе «Трамвай» и
> «трамвай» пройдут как разные команды.

## 2. Миграции

### Через панель Supabase

SQL Editor → выполните по очереди, строго по порядку номеров:

```
supabase/migrations/0001_schema.sql
supabase/migrations/0002_functions.sql
supabase/migrations/0003_views.sql
supabase/migrations/0004_rls.sql
supabase/migrations/0005_storage.sql
supabase/migrations/0006_seed_event.sql
```

Каждый файл выполняется целиком, одним запуском.

### Через Supabase CLI

```bash
npx supabase link --project-ref <ваш-ref>
npx supabase db push
```

**Не применяйте** `supabase/local/00-supabase-shim.sql` — это
заглушки для локального Postgres. На Supabase эти объекты уже
есть, и shim их сломает.

### Проверка

```sql
SELECT count(*) FROM public.tasks;              -- 12 демо-заданий
SELECT slug, status FROM public.events;         -- leipzig-2026, registration
SELECT id, public FROM storage.buckets;         -- 4 бакета
SELECT count(*) FROM pg_policies
  WHERE schemaname = 'public';                  -- политики RLS на месте
```

### Совместимость с Supabase

Все конструкции миграций, которые на Supabase могут вести себя
иначе, чем на чистом PostgreSQL, проверены на живом проекте:

| Что | Результат |
|---|---|
| Локаль базы | `en_US.UTF-8` — `lower()` понимает кириллицу |
| Роли `anon`, `authenticated`, `service_role` | на месте |
| `auth.jwt()`, `auth.uid()` | на месте |
| `storage.foldername(text)` | на месте, политика бакетов работает |
| Политики на `storage.objects` | создаются, хотя владелец таблицы другой |
| `INSERT ... ON CONFLICT DO UPDATE` в `storage.buckets` | работает |

> **Удалить бакет через SQL нельзя.** Триггер
> `storage.protect_delete()` блокирует прямое удаление из таблиц
> хранилища и отвечает кодом `42501`. Это защита от осиротевших
> объектов. Бакеты удаляются через панель Supabase или Storage
> API. Миграции ничего не удаляют, поэтому на установку это не
> влияет — но знать полезно.

## 3. Переменные окружения

Скопируйте `.env.example` в `.env.local` и заполните.

Из Supabase → Project Settings → API:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://<ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon / publishable>
SUPABASE_SERVICE_ROLE_KEY=<service_role — только сервер!>
```

Секреты сгенерируйте:

```bash
openssl rand -base64 48   # SESSION_SECRET
openssl rand -hex 32      # WORKER_SECRET
openssl rand -hex 32      # CRON_SECRET
```

`SESSION_SECRET` — не короче 32 символов. Его смена разлогинивает
все команды: не меняйте в день мероприятия.

Gemini — по желанию:

```bash
GEMINI_API_KEY=<ключ или пусто>
GEMINI_MODEL=gemini-2.5-flash
```

Без ключа приложение работает полностью, фотографии идут в ручную
проверку.

## 4. Локальный запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:3000

## 5. Администратор

```bash
node scripts/create-admin.mjs you@example.com "надёжный-пароль"
```

Скрипт заводит пользователя в Supabase Auth и добавляет строку в
`admin_users`. Без второго шага вход не даст никаких прав.

Пароль можно не указывать — тогда он сгенерируется и покажется
один раз.

Вход: `/admin/login`

## 8. Vercel

```bash
npx vercel link
npx vercel --prod
```

Или через интерфейс: New Project → импорт репозитория.

### Переменные на Vercel

Перенесите всё из `.env.local`, плюс:

```bash
NEXT_PUBLIC_APP_URL=https://ваш-домен.vercel.app
CRON_SECRET=<сгенерированный>
```

`NEXT_PUBLIC_APP_URL` нужен для ссылок-приглашений: без него они
будут вести на localhost.

### Cron

`vercel.json` уже настроен: `/api/worker/validate` раз в минуту.

Cron на бесплатном тарифе выполняется раз в сутки. Для квеста
нужен тариф Pro либо внешний планировщик, дёргающий эндпоинт с
заголовком `x-worker-secret`.

Без cron проверка всё равно работает: она запускается сразу
после подтверждения загрузки через `after()`. Cron нужен как
страховка для зависших задач.

## 9. Проверка перед мероприятием

```bash
npm run verify    # typecheck + lint + тесты + сборка
```

Вручную на боевом домене:

- [ ] Главная открывается, дата и цена верные.
- [ ] Регистрация команды проходит, код приходит.
- [ ] Вход по коду с другого устройства работает.
- [ ] Вход в админку работает.
- [ ] Задания импортированы, число на главной совпадает.
- [ ] Запуск квеста открывает задания у команды.
- [ ] Фотография загружается с телефона.
- [ ] Отправка появляется в очереди организатора.
- [ ] Принятие начисляет баллы, рейтинг обновляется.
- [ ] Экспорт CSV скачивается и открывается в Excel.
- [ ] Приложение ставится на телефон как PWA.
- [ ] Всё проверено и на Android, и на iPhone.

## 10. В день мероприятия

**За неделю.** Импортировать задания, проверить критерии,
прогнать полный цикл на тестовой команде.

**За день.** Открыть регистрацию, разослать ссылку. Убедиться,
что оплата отмечена у всех команд.

**За час.** Закрыть регистрацию. Проверить состав команд.
Открыть админку на ноутбуке.

**В момент старта.** Кнопка «Запустить квест» на сводке. Задания
становятся видны всем немедленно.

**Во время.** Держать открытой очередь проверки. Разбирать
`manual_review` по мере поступления — после решения открывается
следующая фотография.

**За час до финиша.** Заморозить рейтинг, если хотите сохранить
интригу.

**После.** «Завершить квест» → досмотреть очередь → разморозить
рейтинг → объявить результаты → выгрузить CSV.

## Резервный сценарий

Если что-то пойдёт не так — [INCIDENT_PLAN.md](./INCIDENT_PLAN.md).
Распечатайте его или откройте на телефоне заранее.

Короткая версия: **мероприятие можно провести полностью вручную**.
Выключите автоматическую проверку в настройках, и все фотографии
пойдут к вам.

## Стоимость

| Сервис | Тариф | Хватает ли |
|---|---|---|
| Supabase | Free | 500 МБ базы, 1 ГБ хранилища — с запасом |
| Vercel | Free | Хостинг да, cron — раз в сутки |
| Vercel | Pro, $20/мес | Нужен для минутного cron |
| Gemini | оплата по факту | Единицы центов на 500 фотографий |

Минимально работающая конфигурация — бесплатная, если смириться
с тем, что зависшие задачи подбираются кнопкой, а не автоматически.

## Обслуживание

**Фотографии** удаляются по сроку хранения кнопкой в
`/admin/settings`. Записи об отправках остаются: журнал
начислений не должен разъезжаться из-за уборки файлов.

**Счётчики лимитов** чистятся функцией `prune_rate_limits()`.

**Следующее мероприятие** заводится через админку: новая дата,
новый импорт заданий. Код менять не нужно.
