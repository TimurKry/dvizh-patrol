# Бриф на редизайн

Документ написан как **вход для другой модели**: его можно скопировать
целиком и попросить вернуть концепцию, JSON-описание токенов или
конкретные экраны. Всё, что нужно для работы, — здесь; лазить в
репозиторий не требуется.

---

## 1. Что это за продукт

Мобильное веб-приложение городского фото-квеста «Движ-Патруль».

Одно мероприятие: **Лейпциг, 15 августа 2026, старт в 15:00,
15 € с человека.** До 10 команд по 4 человека, 30–50 фото-заданий,
до 500 фотографий за вечер.

Команда регистрируется, получает шестизначный код, в момент старта
видит список заданий, ходит по центру города, снимает на телефон,
отправляет фотографии. Часть проверяется автоматически, спорное
разбирает организатор. Баллы и рейтинг считаются на сервере.

**Никаких аккаунтов, email и паролей у участников нет** — только код
команды.

## 2. Кто и в каких условиях этим пользуется

Это определяет дизайн сильнее, чем вкусовые предпочтения.

|                     |                                              |
| ------------------- | -------------------------------------------- |
| Устройство          | телефон, почти всегда одной рукой            |
| Место               | улица, движение, спешка                      |
| Время               | вечер августа, от дневного солнца до сумерек |
| Состояние           | азарт, шум, компания, часто алкоголь         |
| Связь               | городской мобильный интернет, местами рвётся |
| Длительность сессии | 3–4 часа непрерывно                          |

Отсюда: **экран должен читаться на ходу, при боковом солнце, за
полсекунды.** Мелкий низкоконтрастный текст здесь не просто некрасив
— он не работает.

Организатор в это же время сидит с ноутбуком и разбирает очередь
фотографий. Его интерфейс — плотный и информационный, не витринный.

## 3. Фирменный стиль: постер

Есть **утверждённый постер** (1122×1402), он не обсуждается и не
меняется. Сайт должен читаться как его продолжение.

Что на постере:

- вертикальный плакат, тёплый кремовый лист;
- гигантское `LEIPZIG` кирпично-красным, узкий гротеск в капители,
  занимает треть высоты;
- под ним `ДВИЖ ПАТРУЛЬ` тем же шрифтом, кегль вдвое меньше;
- разряженная подпись `ГОРОДСКОЙ ФОТО-КВЕСТ` между тонкими линейками;
- **фотография города в сепии, вырастающая снизу** — ратуша с башней,
  почти чёрная на фоне кремового неба;
- нижняя строка `15.08 · ДАТА` / `15:00 · СТАРТ` / `15€ · УЧАСТИЕ`
  с иконками-контурами;
- тонкая рамка по краю листа, ромбы-разделители `◆`;
- заметная типографская зернистость — это печать, а не экран.

**Ключевое, что сейчас потеряно: на постере огромный перепад
светлоты.** Почти чёрное здание против кремового листа. Красный —
акцент на 9% площади, не заливка.

## 4. Жёсткие ограничения

Не предмет обсуждения. Решение, которое их нарушает, не подходит.

### Палитра

Снята пипеткой с постера и посчитана по долям площади.

```
--color-canvas         #f0dbc9   фон страницы, 47% площади постера
--color-canvas-deep    #e7cdb8   чередующиеся полосы, подложки
--color-paper          #faefe5   карточки и поля

--color-brick          #9b1c17   акцент, контраст на холсте 6.6:1
--color-brick-deep     #7e150f   нажатие, hover
--color-brick-soft     #b6371b   осветлённый оттенок с постера

--color-ink            #2b1a14   текст, контраст 13.4:1
--color-sepia          #6b4636   абзацы, 6.6:1
--color-sand           #8a6a55   подсказки, 3.9:1 — только крупный текст

--color-hairline        rgb(43 26 20 / 0.14)
--color-hairline-strong rgb(43 26 20 / 0.26)
--color-brick-line      rgb(155 28 23 / 0.32)
--color-ink-wash        rgb(43 26 20 / 0.05)
--color-brick-wash      rgb(155 28 23 / 0.07)
```

Новые оттенки вводить можно, но **только производные от этих** —
чужие цвета (синий, зелёный, серый) запрещены. Белый `#ffffff` и
чёрный `#000000` не использовать никогда: тёмный тон тёплый.

### Шрифты

```
--font-poster  Oswald    плакатные заголовки, капитель
--font-text    Literata  текст, абзацы
```

**Кириллица обязательна.** Исходное ТЗ предлагало Fraunces — в нём
нет кириллицы, а весь интерфейс русскоязычный. Любая замена шрифта
обязана покрывать кириллицу и иметь вес 300–600.

### Типографическая шкала

```
caption      14px / 1.5
body         16px / 1.5
subheading   18px / 1.29
heading-sm   24px / 1.2
heading      33px / 1.1
heading-lg   38px / 1.08
display      58px / 1.02
display-xl   74px / 0.88
```

Шкалу можно перестроить, но **16px — минимум для полей ввода**:
меньше, и Safari на iPhone зумит страницу при фокусе.

### Обязательные требования

- **Мобильный первым.** Базовая ширина 390px. Десктоп — расширение.
- **Зона нажатия ≥ 44×44px.** Квест проходят на ходу.
- **Контраст:** основной текст ≥ 4.5:1, крупный ≥ 3:1.
- **Статус различим без цвета** — символом, текстом и стилем рамки.
  Требование доступности, не пожелание.
- **`prefers-reduced-motion`** отключает всё движение, элементы
  остаются в конечном состоянии, а не исчезают.
- **Масштабирование не запрещать** (`maximum-scale=5`).
- Анимировать **только `transform` и `opacity`** — остальное
  пересчитывает раскладку и дёргается на дешёвом телефоне.

### Технические рамки

- Next.js 16 (App Router), React 19, TypeScript strict.
- **Tailwind CSS v4**, токены в блоке `@theme`. Никакого CSS-in-JS,
  никаких новых зависимостей ради стилей.
- Тёмной темы нет и не планируется — свет один.
- Иконки — инлайновый SVG или типографские символы. Иконочные
  библиотеки не подключать.

## 5. Что не так сейчас

Честный диагноз текущего состояния. Оценка заказчика — 2/10, и она
справедлива.

1. **Всё бежевое на бежевом.** Фон `#f0dbc9` и карточки `#faefe5`
   различаются на 4% светлоты. Карточки не читаются как отдельный
   слой, страница сливается в одно пятно.

2. **Тёмный тон ни разу не работает поверхностью.** `#2b1a14` есть
   только в тексте. В макете нет ни одного тёмного пятна, которое
   держало бы композицию, — а на постере оно занимает нижнюю треть.

3. **Вторичная кнопка почти невидима** — бумага на холсте, разница
   на грани различимости.

4. **Статусы и теги — россыпь тонких контурных пилюль.** Визуальный
   шум, низкий контраст, выглядит недоделанным.

5. **Ровный масштаб.** Заголовки разных уровней близки по кеглю и
   весу, ничего не доминирует. На постере перепад в разы.

6. **Однообразный ритм отступов.** Нет ни воздуха, ни плотности —
   всё на одном расстоянии, глазу не за что зацепиться.

7. **Плоско и стерильно.** Постер напечатан и зернист, интерфейс —
   ровная цифровая заливка. Фактура есть только в одном блоке.

Итог: сайт **заявляет** родство с постером, а выглядит как его
выцветшая копия.

## 6. Задача

Сделать так, чтобы человек, увидевший постер, узнал сайт мгновенно,
а человек на улице прочитал экран за полсекунды.

### Что решить в первую очередь

1. **Вернуть перепад светлоты.** Нужны настоящие тёмные плоскости, а
   не только тёмный текст. Где именно — решать вам: герой, полосы
   между секциями, шапка, нижняя панель.
2. **Развести слои.** Карточка обязана читаться как отдельный
   предмет на листе.
3. **Усилить иерархию.** Резкие перепады кегля вместо плавных.
4. **Собрать статусы и теги** в систему, которая не выглядит
   мусором из контуров.
5. **Добавить фактуру** печати там, где она уместна.
6. **Разметить ритм:** плотные информационные зоны против
   просторных витринных.

### Экраны

Участник:

| Экран               | Что на нём                                                                                        |
| ------------------- | ------------------------------------------------------------------------------------------------- |
| Главная             | постер, дата, цена, обратный отсчёт, две кнопки, механика в 4 шага, примеры заданий, правила, BBQ |
| Регистрация команды | название, капитан, контакт, согласия                                                              |
| Вход по коду        | код из 6 символов, имя, согласия                                                                  |
| Команда             | код приглашения, состав, баллы, место                                                             |
| Список заданий      | 30–50 карточек: номер, фото-эталон, название, баллы, статус, попытки; фильтры и сортировка        |
| Задание             | эталон, условие, критерии, карта, загрузка фото, история попыток                                  |
| Отправки            | лента: превью, задание, статус, баллы                                                             |
| Рейтинг             | таблица команд                                                                                    |
| Карта               | игровое поле, точки заданий                                                                       |

Организатор (плотный рабочий интерфейс, не витрина):

| Экран            | Что на нём                                                     |
| ---------------- | -------------------------------------------------------------- |
| Сводка           | статус квеста, счётчики, кнопки запуска и остановки            |
| Очередь проверки | фотография крупно, критерии, принять / отклонить / комментарий |
| Команды          | таблица, оплата, баллы                                         |
| Задания          | список, редактор, импорт файлом                                |
| Настройки        | параметры мероприятия, игровое поле, срок хранения фото        |

### Особые состояния

Их нельзя забывать — на них приходится половина вечера:

- задания закрыты до старта;
- фотография загружается / проверяется / принята / отклонена /
  ждёт организатора;
- попытки кончились;
- нет связи (приложение работает как PWA);
- квест приостановлен, завершён, рейтинг заморожен;
- мест нет, регистрация закрыта.

## 7. Что не трогать

- **Функциональность и логику.** Дизайн меняет вид, не поведение.
- **Тексты интерфейса** — они выверены и живут в `lib/messages.ts`.
  Переписывать можно только по отдельной просьбе.
- **Структуру данных и маршруты.**
- **Постер** — он утверждён.

## 8. Что считается результатом

Концепция принимается, если:

- [ ] на любом экране есть хотя бы одно **тёмное или насыщенное
      пятно**, держащее композицию;
- [ ] карточка визуально отделена от фона без теней;
- [ ] красный остаётся акцентом на **один-два элемента экрана**,
      а не заливкой;
- [ ] на экране 390px главное читается **без прокрутки**;
- [ ] статус отправки понятен **в чёрно-белой печати**;
- [ ] все кнопки и ссылки ≥ 44px по короткой стороне;
- [ ] контраст текста проверен и вписывается в нормы;
- [ ] узнаётся родство с постером — палитра, шрифт, линейки, ромбы;
- [ ] ничего не мигает и не дёргается при `prefers-reduced-motion`.

именно это:

    {
      "name": "имя",
      "background": "токен",
      "text": "токен",
      "border": "токен",
      "when": "где применяется"
    }
  ],
  "components": [
    {
      "name": "Button/primary",
      "spec": "описание",
      "states": ["default", "hover", "active", "disabled", "focus"]
    }
