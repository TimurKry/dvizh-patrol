# Выкладка в сеть

Как поднять квест на настоящем адресе, потратив ноль или почти
ноль, и не отдать при этом задания раньше времени.

## Коротко

| Что              | Чем                     | Сколько       |
| ---------------- | ----------------------- | ------------- |
| Хостинг          | Vercel Hobby            | 0 €           |
| База и хранилище | Supabase Free           | 0 €           |
| Адрес            | `что-угодно.vercel.app` | 0 €           |
| Свой домен       | регистратор             | 1–10 € в год  |
| Минутный cron    | cron-job.org            | 0 €           |
| AI-проверка      | Gemini, по факту        | центы или 0 € |

Полностью бесплатная конфигурация рабочая. Свой домен — единственное,
за что имеет смысл заплатить, и то не обязательно.

## 1. Кто и что может увидеть

Это первый вопрос, а не последний. Разберём по слоям.

### Репозиторий

Репозиторий **приватный**. Кроме вас его никто не открывает —
ни по ссылке, ни поиском.

Но даже если бы он был публичным, **реальных заданий в нём нет**.
В коде лежат только:

- `data/tasks.example.json` и `.csv` — 30 выдуманных заданий-образцов
  для формата импорта;
- `supabase/migrations/0006_seed_event.sql` — 12 демонстрационных
  заданий, чтобы приложение было чем наполнить сразу после
  установки.

Ваши настоящие 50 заданий живут **только в базе** и попадают туда
через `/admin/import`. Ни в одном коммите их нет и не будет.

> **Не коммитьте файл с реальными заданиями.** Держите его у себя
> на компьютере или в облаке. Если очень нужно положить рядом —
> добавьте имя файла в `.gitignore` до того, как сделаете `git add`.

### Браузер участника

Опаснее гита. Пока квест не запущен, задания закрыты **тремя
независимыми преградами**:

1. **Политика базы.** У роли `anon` есть право читать `tasks`, но
   политика `tasks_read_active` пропускает строки только когда
   мероприятие видимо. До старта запрос возвращает ноль строк —
   не «ошибку доступа», а пустоту.
2. **Страницы не загружают закрытое.** `/tasks` и `/tasks/[id]`
   проверяют статус мероприятия **до** обращения к базе. Пока
   квест не запущен, формулировки просто не читаются: нечему
   утекать ни в разметку, ни в сетевой ответ.
3. **Участники вообще не ходят в базу напрямую.** У команд нет ни
   одной политики на запись, а чтение идёт через сервер, который
   знает команду из httpOnly cookie. Ключ `anon`, который попадает
   в браузер, сам по себе не открывает ничего.

Проверить перед мероприятием (статус должен быть «Регистрация»):

- [ ] войти командой, открыть `/tasks` — «Задания ещё закрыты»;
- [ ] в инструментах разработчика, вкладка Network, обновить
      страницу и поискать по ответам текст любого задания —
      не должно найтись;
- [ ] открыть `/tasks/<любой-id>` руками — та же заглушка.

### Организаторская

`/admin` закрыт входом по email и паролю через Supabase Auth,
и отдельно — строкой в таблице `admin_users`. Одного пароля мало:
пользователь без этой строки не получит ничего.

Заводите ровно столько администраторов, сколько людей реально
будут разбирать очередь.

## 1a. Бесплатный Supabase засыпает

**Проект на тарифе Free паузится примерно после недели без
запросов.** Спящий проект не отвечает: приложение показывает
ошибку подключения, а SQL-запросы отваливаются по таймауту.

Это не поломка и не потеря аккаунта — проект будится кнопкой
Restore в панели Supabase. Но пробуждение занимает **минуты, а не
секунды**, и всё это время сайт не работает.

Что с этим делать:

- **Не оставляйте проект без дела перед мероприятием.** Заходите
  на сайт хотя бы раз в несколько дней — этого достаточно.
- **Разбудите заранее, а не в день квеста.** Проверьте статус
  проекта за сутки: панель Supabase → проект должен быть
  `Active healthy`.
- **Если проект уже уснул** — нажмите Restore и дождитесь, пока
  схема поднимется целиком. Проверить:

```sql
SELECT count(*) FROM public.tasks;   -- должно отвечать, а не падать
```

> **Проверьте данные после пробуждения.** Если `public` оказалась
> пустой, накатите миграции `0001`–`0007` заново — они
> восстанавливают схему, демо-мероприятие и демо-задания
> целиком. Реальные задания придётся импортировать повторно из
> вашего файла, поэтому **держите файл импорта у себя**, а не
> только в базе.

Платный тариф Pro не паузит проекты. Если нервничать не хочется,
20 $ за один месяц вокруг мероприятия — разумная страховка.

## 2. Адрес

### Бесплатно: поддомен Vercel

При деплое проект получает адрес вида
`dvizh-patrol.vercel.app` — с сертификатом, сразу и навсегда.
Имя выбираете сами при создании проекта.

Для одного вечера этого достаточно. Ссылку всё равно рассылают
в мессенджере, а не диктуют голосом.

### 1–10 € в год: свой домен

Если хочется `dvizh-patrol.de` или `dvizhpatrol.xyz`:

1. Купить у любого регистратора. Дешёвые зоны (`.xyz`, `.site`,
   `.online`) стоят около 1–3 € за первый год; `.de` — около
   5 € в год. **Cloudflare Registrar** продаёт по себестоимости,
   без наценки на продление — если планируете держать домен
   несколько лет, это самый честный вариант.
2. В Vercel: Project → Settings → Domains → Add.
3. Vercel покажет, какие DNS-записи прописать у регистратора.
   Прописать, подождать. Обычно минуты, изредка до суток.
4. Сертификат Vercel выпустит сам.

Не забудьте после этого поменять `NEXT_PUBLIC_APP_URL` на новый
адрес: из него собираются ссылки-приглашения.

> **Бесплатных доменов не берите.** Зоны вроде `.tk` и `.ml`
> регулярно отзывают имена без предупреждения. Потерять адрес за
> день до мероприятия — плохой способ сэкономить два евро.

## 3. Тариф Vercel — что проверить

Hobby бесплатный и покрывает всё, что нужно этому проекту по
нагрузке: 10 команд и 500 фотографий он не заметит.

Две оговорки, которые стоит знать заранее.

**Коммерческое использование.** Условия Hobby написаны под личные
некоммерческие проекты. Квест с платным участием формально в эту
рамку может не попасть. Риск невелик — это разовое мероприятие на
сорок человек, а не бизнес, — но решение ваше. Если хотите быть
чистыми: Pro стоит 20 $ в месяц, и его можно включить на один
месяц и выключить.

**Cron.** Hobby разрешает планировщику **только суточное**
расписание, и это не мягкое ограничение: деплой с `* * * * *`
в `vercel.json` просто **не создаётся** — Vercel отвечает
«Hobby accounts are limited to daily cron jobs». Поэтому в
репозитории стоит `0 3 * * *`.

На работу это не влияет: проверка фотографии запускается сразу
после загрузки через `after()`, а cron нужен лишь как страховка
для задач, зависших из-за обрыва связи. Зависшие можно поднять и
руками — кнопка «Обработать зависшие» в `/admin`.

Если нужна минутная страховка:

- **тариф Pro** — поменяйте `schedule` в `vercel.json` на
  `* * * * *` и передеплойте;
- **или бесплатный внешний планировщик**, например cron-job.org:

- URL: `https://ваш-домен/api/worker/validate`
- Метод: POST
- Заголовок: `x-worker-secret: <ваш WORKER_SECRET>`
- Интервал: раз в минуту

Эндпоинт без правильного секрета отвечает отказом, так что
светить адресом не страшно.

## 4. Порядок выкладки

```bash
npx vercel link
npx vercel --prod
```

Или через интерфейс: New Project → импорт репозитория.

### Переменные окружения на Vercel

Перенесите всё из `.env.local` и поправьте адрес:

```bash
NEXT_PUBLIC_APP_URL=https://ваш-домен
```

`SUPABASE_SERVICE_ROLE_KEY`, `SESSION_SECRET`, `WORKER_SECRET`,
`CRON_SECRET`, `GEMINI_API_KEY` — задавайте **без** префикса
`NEXT_PUBLIC_`. Всё, что с этим префиксом, уезжает в браузер.

Отметьте их как доступные для Production, Preview и Development —
иначе предпросмотр веток будет падать на проверке конфигурации.

### Preview-развёртывания

Vercel поднимает отдельный адрес на каждую ветку. Эти адреса
не индексируются, но **ссылку можно переслать**. Если не хотите,
чтобы кто-то наткнулся на черновик, включите защиту:
Project → Settings → Deployment Protection → Vercel Authentication.

Она же закроет и продакшен, если включить на всё, — так что
выбирайте «только Preview».

### Линтер Supabase после каждой миграции

Дашборд → Advisors → Security, или `get_advisors` через MCP.
Прогонять **после каждого наката**, а не раз перед стартом: одна
из находок так и появилась — `0009` выдала права `service_role`
функциям руки, но не отняла те, что PostgreSQL раздаёт сам, и
`get_team_hand` некоторое время была вызываема публичным ключом.
Закрыто в `0011`.

Что остаётся в списке и почему это нормально:

| Находка                                                            | Почему оставлено                                                                                                          |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| `rate_limits`, `team_sessions`: RLS включена, политик нет          | Так и задумано: обе таблицы — служебные, доступ только через `service_role` и `SECURITY DEFINER`. Пустой набор политик и означает «никому». |
| `is_admin()`, `current_team_id()` вызываемы анонимно               | Обе без аргументов и отвечают только про вызывающего. Подставить чужой идентификатор некуда.                              |
| `event_tasks_visible(uuid)` вызываема анонимно                     | Возвращает `boolean` о статусе мероприятия, не список заданий.                                                            |
| Leaked password protection выключена                               | Настройка Auth, а не кода: включается тумблером в Authentication → Policies. Касается только организаторских аккаунтов — участники паролей не заводят. |

Всё, чего в этой таблице нет, — новое, и разбирать его нужно, а не
списывать на шум.

## 5. Настоящие задания

Демонстрационные двенадцать приезжают вместе с миграцией. Когда
будете импортировать свои 50, поставьте на `/admin/import`
галочку **«Заменить существующие»** — демо-задания удалятся.

Удаляются только те, по которым ещё нет ни одной отправки: иначе
пропали бы уже начисленные баллы. Поэтому импортируйте **до**
старта, а не по ходу.

Проверьте после импорта:

- [ ] на главной число заданий стало 50;
- [ ] в `/admin/tasks` нет заданий с чужими названиями;
- [ ] у заданий с режимом `ai` заполнены критерии.

## 6. Что сделать в последний час

- [ ] проект Supabase `Active healthy`, а не спящий;
- [ ] `NEXT_PUBLIC_APP_URL` совпадает с реальным адресом;
- [ ] на боевом домене открывается главная, дата и цена верные;
- [ ] регистрация проходит, код приходит;
- [ ] вход по коду работает с чужого телефона;
- [ ] `/admin/login` пускает;
- [ ] задания импортированы и **закрыты** до старта;
- [ ] фотография загружается с телефона, а не только с ноутбука;
- [ ] приложение ставится на телефон как PWA;
- [ ] проверено и на Android, и на iPhone.

Полный список проверок — в [DEPLOYMENT.md](./DEPLOYMENT.md).
Если что-то пойдёт не так — [INCIDENT_PLAN.md](./INCIDENT_PLAN.md).
