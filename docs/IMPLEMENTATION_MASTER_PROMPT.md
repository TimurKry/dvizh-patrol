Ты — lead full-stack engineer и design implementation owner проекта
«Движ-Патруль». Работай непосредственно в репозитории
`https://github.com/TimurKry/dvizh-patrol` и доведи существующий продукт до
полностью рабочего production-состояния. Это не генерация нового проекта и не
редизайн с нуля: архитектура, база, RLS, серверные действия и большая часть
функций уже существуют. Сохраняй рабочую логику, а визуал и недостающие функции
доводи системно.

## Главная цель

Из актуального Figma-проекта и существующего backend получить один целостный
сайт: лендинг, мобильную игру участника, PWA и плотную админ-панель. Все реальные
действия должны работать, а не быть кликабельными макетами. Не оставляй TODO,
фиктивные кнопки, моковые данные в production-пути или экран без нужного state.

## Источники истины и приоритет

## Запрещённое старое направление

Не возвращай бежевую/кирпичную тему, постерный layout, Oswald, Literata,
пяти-пунктную нижнюю навигацию или старые изображения интерфейса. Единственная
система — Mono Signal:

- canvas `#060609`;
- panel `#121216`;
- paper/ink `#F5F5F1`;
- muted `#A3A3A8`;
- hairline `#404045`;
- signal `#FF00B3`;
- display font Unbounded 500–700;
- UI/body font Onest 400–600.

Основной интерфейс чёрно-белый. Пурпурный — один главный сигнал. Цвета команд
разрешены только в игровых рубашках, орнаментах, командных маркерах и связанных
с командой деталях.

## Обязательные сценарии

### Лендинг

Собери Figma `74:3`/`87:2`: плавающие чёрно-белые полароиды, цвет при
hover/focus на desktop, центральный title, дата/время/цена, countdown, билетные
CTA, карта, flip-примеры, расписание, BBQ и footer. «Создать команду» открывает
Telegram менеджера, «Войти по коду» — `/join`.

### Карточная механика и гонка

У каждой команды есть цвет из набора: red `#FF3B30`, green `#21C55D`, blue
`#2F80FF`, yellow `#FFD400`, orange `#FF7A00`, pink `#FF00B3`. Храни значение в
БД как ограниченный enum/string, а визуальные hex — в одном mapping-файле.

Во время игры команда видит руку из 6 карточек: 2 загадки, 2 фото-повтора,
2 городских актива. Сервер выдаёт их случайно из доступного пула. Не загружай весь
скрытый пул в браузер. Tap/click/keyboard переворачивает карточку за 420ms с
perspective 900px; только transform и opacity.

Первая **валидно принятая** отправка атомарно забирает задание глобально. После
commit оно исчезает у остальных команд, а их руки пополняются. Это должна
обеспечивать база уникальным ограничением/транзакцией, а не проверка в React.
Параллельные accept не могут начислить баллы двум командам. Добавь интеграционный
тест с конкурентными транзакциями и понятное состояние «задание уже забрала
другая команда». Баллы задаёт организатор; диапазон не хардкодить.

### Навигация участника

Постоянных пунктов ровно три: `Задания /tasks`, `Команда /team`, `Ещё /more`.
Карта, отправки, рейтинг, правила и участники находятся в «Ещё». Отправка ответа
является контекстным действием внутри задания. Offline — banner/state, не tab.

### Админка

Реализуй все A00–A12. Организатор должен управлять мероприятием, командами,
оплатой, цветами, заданиями, баллами, попытками, критериями, импортом, очередью,
рейтингом, сроком хранения и audit log.

Редактор игрового поля должен позволять поставить точки на карте, собрать
полигон, двигать/удалять точки, очистить и сохранить. Храни GeoJSON/JSONB с
валидацией; PostGIS ради одного полигона не добавляй без доказанной необходимости.
Существующие координаты отдельных заданий и privacy-правила сохранить.

### Связь и PWA

Фото сжимается и очищается от EXIF на устройстве. Повтор после обрыва не создаёт
дубликат благодаря idempotency key. Статус очереди восстанавливается после
перезапуска. Service worker не кэширует API/admin и не показывает устаревшие
баллы как свежие.

## Accessibility и motion

- mobile-first, контроль на 390px;
- desktop admin проверять на 1440px и обычном ноутбуке;
- touch target минимум 44×44px;
- поля минимум 16px;
- основной контраст минимум 4.5:1;
- статус: символ + текст + рамка, никогда только цвет;
- не запрещать zoom, `maximum-scale=5`;
- анимировать только transform/opacity;
- `prefers-reduced-motion` сразу показывает конечное состояние;
- flip доступен кнопкой и клавиатурой, лицевая/оборотная сторона корректно
  скрываются от screen reader.

## Непрерывный рабочий цикл

1. Прочитай `CLAUDE.md`, этот prompt, checklist и профильные docs.
2. Проверь git status и существующую реализацию; не стирай рабочую логику.
3. Обнови checklist реальными подзадачами и статусами.
4. Выбери первый незавершённый вертикальный slice.
5. Получи Figma context нужных узлов.
6. Реализуй UI + server/data часть + состояния + тесты.
7. Запусти релевантные тесты и визуально проверь 390/1440.
8. Обнови checklist и документацию.
9. Снова прочитай checklist и **сразу продолжи со следующим пунктом**.

Не заканчивай ответ словами «дальше можно сделать». Продолжай самостоятельно,
пока checklist полностью не закрыт. Допустимая остановка: отсутствует конкретный
секрет/доступ, миграция требует подтверждения production-операции или обнаружен
риск потери данных. В таком случае укажи один точный blocker и команду/доступ,
которые нужны.

## Проверка перед завершением

Обязательно:

```bash
npm ci
npm run typecheck
npm run lint
npm run test
npm run test:integration
npm run build
npm run test:e2e
```

Integration/E2E выполнять только на локальной или отдельной test/preview базе,
поскольку quest-flow меняет статус события. Дополнительно проверь:

- конкурентный глобальный захват задания;
- регистрацию/вход по коду на двух телефонах;
- загрузку фото при плохой связи;
- все специальные состояния;
- PWA install/offline shell;
- админский CRUD и polygon editor;
- отсутствие горизонтального scroll;
- отсутствие layout-анимаций;
- отсутствие старой палитры и архивных ассетов.

Финальный отчёт должен содержать выполненный checklist, миграции, результаты
тестов, preview URL, известные ограничения и rollback-инструкцию.
