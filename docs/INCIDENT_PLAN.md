# Что делать, если что-то пошло не так

Откройте эту страницу на телефоне до начала квеста.

---

## Главное

**Мероприятие можно провести полностью вручную.** Автоматическая
проверка — удобство, а не необходимость. Если она отказала,
выключите её и разбирайте фотографии сами: квест не
останавливается.

Фотографии не теряются ни при одном из сценариев ниже.

---

## Отказала автоматическая проверка

**Признаки:** отправки копятся в «Ожидают», на вкладке «Ошибки
проверки» растёт число.

**Что делать:**

1. `/admin/event` → снять флажок «Автоматическая проверка
   включена» → сохранить.
2. `/admin/submissions` → «Всё — в ручную проверку».

Все новые фотографии пойдут прямо к вам. Уже ожидающие
переведутся немедленно.

**Что увидит участник:** «Фотография ожидает ручной проверки».
Никаких технических ошибок.

---

## Кончилась квота Gemini

То же самое. Разница лишь в причине — на итог она не влияет.

Если квоту восстановили: включите проверку обратно и нажмите
«Обработать зависшие».

---

## Отправки застряли в «Проверяется»

**Признаки:** число в «Проверяются» не убывает больше пяти минут.

**Что делать:** `/admin` → «Повторно обработать зависшие».

Кнопка возвращает в очередь задачи умершего обработчика и
подбирает отправки, потерявшие свою задачу. Ответ покажет,
сколько восстановлено.

**Безопасно ли повторять:** да. Повторная обработка не начисляет
баллы дважды — это гарантировано уникальным индексом в базе.

---

## Команда не может отправить фотографию

**По шагам:**

1. **Квест запущен?** `/admin` → статус должен быть «Идёт».
   В паузе отправки заблокированы.
2. **Задание активно?** `/admin/tasks` → колонка «Состояние».
3. **Попытки не кончились?** Страница задания у команды покажет
   остаток.
4. **Задание уже засчитано?** Тогда новая отправка запрещена —
   это правило, а не сбой.
5. **Связь.** Пусть отойдут на несколько шагов. Выбранная
   фотография сохранена и не потеряется.

**Если нужно дать ещё попытку:** `/admin/tasks/<id>` → увеличьте
`maxAttempts`.

---

## Команда потеряла доступ

Телефон разрядился, вкладка закрылась, cookie исчезла.

**Решение:** пусть войдут заново по коду команды на `/join`.
Имя вводят то же — новое место в команде не занимается.

**Если код забыли:** `/admin/teams/<id>` — код виден там же.

**Если код скомпрометирован:** «Новый код приглашения». Старый
перестанет работать немедленно.

---

## Кто-то вошёл в чужую команду

1. `/admin/teams/<id>` → «Сбросить сессии» — выбьет всех.
2. «Новый код приглашения».
3. Раздайте новый код своим участникам.
4. При необходимости удалите лишнего участника.

---

## Ошиблись с решением по фотографии

**Приняли зря:** откройте отправку → «Отклонить». Баллы снимутся
обратной транзакцией, история сохранится.

**Отклонили зря:** откройте отправку → «Принять». Можно указать
другое количество баллов.

**Приняли не ту фотографию:** отклоните её, затем примите нужную.
Пока действующего начисления нет, задание можно принять заново.

Всё это фиксируется в `/admin/audit`.

---

## Не сходятся баллы

**Смотреть здесь:** `/admin/teams/<id>` → «Журнал начислений».
Там каждая операция с причиной и отметкой об отмене.

Сумма журнала — это и есть счёт команды. Отдельного счётчика в
базе нет, поэтому «рассинхронизации» быть не может по устройству.

**Скорректировать вручную:** там же — бонус, штраф или
корректировка с обязательным указанием причины.

---

## Регистрация переполнена

**«Все места заняты», а команда должна играть:**

1. `/admin/teams` → найдите отменённую или лишнюю → «Отменить
   регистрацию». Место освободится.
2. Либо `/admin/event` → поднимите лимит (максимум 10).
3. Либо `/admin/teams` → «Создать команду вручную» — обходит окно
   регистрации, но не лимит.

**Лимит нельзя опустить** ниже числа уже зарегистрированных
команд: иначе кто-то оказался бы сверх лимита задним числом.

---

## Пятый участник в команде

Не пройдёт: лимит проверяется в базе под блокировкой.

**Если человек всё же должен играть:** `/admin/event` →
увеличьте «Человек в команде». Изменение действует сразу.

---

## Рейтинг показывает не то

`/admin/leaderboard`:

- **Скрыть полностью** → «Скрыт».
- **Только своё место** → «Только своё место».
- **Зафиксировать** → «Заморожен». Сохранится снимок; вы
  продолжите видеть реальную таблицу, участники — замороженную.
- **Вернуть** → «Виден всем». Снимок удалится.

---

## Долго открывается админка

Обычно это очередь проверки с сотнями строк.

- Пользуйтесь вкладками, а не «Все».
- Фильтруйте по команде или заданию.
- Списки уже постраничные по 40 и открывают превью, а не
  оригиналы.

---

## Нужно принять сразу всё по заданию

Задание оказалось неудачным, и спорить о нём не хочется.

`/admin/tasks/<id>` → «Принять все ожидающие». Баллы начислятся
всем, у кого есть неразобранная отправка по этому заданию.

---

## Совсем всё сломалось

**Порядок действий:**

1. Не паникуйте: фотографии в хранилище, баллы в журнале.
2. Выключите автоматическую проверку.
3. Если недоступна админка — соберите фотографии в мессенджере
   на оставшееся время. Записи внесёте после.
4. После мероприятия: `/admin/import` для заданий,
   ручные начисления для баллов.
5. Выгрузите результаты в CSV.

**Данные не теряются**, даже если приложение недоступно: они в
Supabase, а не в браузере участника.

---

## Полезные команды

Проверить обработчик:

```bash
curl -X POST https://ваш-домен/api/worker/validate \
  -H "x-worker-secret: $WORKER_SECRET"
```

Посмотреть очередь:

```sql
SELECT status, count(*) FROM validation_jobs GROUP BY status;
```

Найти застрявшие отправки:

```sql
SELECT id, status, updated_at FROM submissions
WHERE status = 'checking' AND updated_at < now() - interval '10 minutes';
```

Проверить, что двойных начислений нет:

```sql
SELECT submission_id, count(*) FROM score_transactions
WHERE transaction_type = 'task_accepted'
  AND reversed_by_transaction_id IS NULL
GROUP BY submission_id HAVING count(*) > 1;
-- пусто = всё в порядке
```
