# Как править проект самому

Три способа, от «ничего не устанавливать» до «всё под рукой».
Выбор зависит не от навыка, а от того, что именно правите.

## 1. Мелкие правки текста и стилей — github.dev

Ставить нечего, работает в браузере.

Откройте репозиторий на GitHub и нажмите **точку** (`.`) — откроется
VS Code прямо в браузере, с тем же деревом файлов и поиском.

Дальше:

1. слева вверху выберите ветку `claude/implementation-checklist-2uczrw`
   (по умолчанию откроется `main`, а работа идёт в ней);
2. правьте файлы;
3. вкладка Source Control (третья иконка слева) → написать, что
   поменяли → **Commit & Push**.

Через полторы-две минуты Vercel пересоберёт превью по той же
ссылке. Ничего запускать не нужно.

Так удобно править:

| Что                        | Где                                          |
| -------------------------- | -------------------------------------------- |
| тексты лендинга            | `app/(site)/page.tsx`, `components/landing/`  |
| правила, условия, приватность | `app/(site)/rules|terms|privacy/page.tsx`  |
| замечания для агента       | `docs/IMPLEMENTATION_CHECKLIST.md`            |
| цвета и размеры            | `app/globals.css`, блок `@theme`              |

Чего github.dev не умеет: запускать сайт, тесты и скрипты. Ошибку
в коде вы увидите только когда Vercel не соберётся.

## 2. Всё по-настоящему — VS Code на своей машине

Нужен [Node.js 20+](https://nodejs.org) и Git.

```bash
git clone https://github.com/TimurKry/dvizh-patrol.git
cd dvizh-patrol
git checkout claude/implementation-checklist-2uczrw
npm install
```

Дальше нужен `.env.local` — без него приложение не поднимется.
Возьмите образец и заполните:

```bash
cp .env.example .env.local
```

Значения — в Vercel: Project → Settings → Environment Variables,
у каждой есть кнопка показать. Скопируйте те же, что стоят в
Production. `SUPABASE_SERVICE_ROLE_KEY` — секрет: он даёт полный
доступ к базе мимо всех правил, в браузер и в репозиторий попадать
не должен. `.env.local` уже в `.gitignore`, случайно не уедет.

```bash
npm run dev          # сайт на http://localhost:3000
npm run verify       # типы, линтер, тесты, сборка
```

`npm run verify` стоит прогонять перед пушем: он ловит почти всё,
на чём падает сборка Vercel, и тратит на это полторы минуты вместо
пяти.

Отдельно про базу: `.env.local` с боевыми ключами означает, что
локальный сайт пишет **в боевую базу**. Пока в ней нет настоящих
команд, это не страшно, но помнить надо.

## 3. Терминал в браузере — Codespaces

Компромисс: GitHub → кнопка **Code** → вкладка **Codespaces** →
**Create codespace**. Тот же VS Code, но с терминалом, так что
`npm run dev` и скрипты работают. Секреты всё равно придётся
завести — Settings → Codespaces → Secrets.

У бесплатного тарифа лимит часов в месяц. Для разовых задач удобно,
для постоянной работы дешевле пункт 2.

## Чтобы мы не мешали друг другу

Агент и вы пишете в одну ветку. Правило простое: **перед тем как
поручить мне работу, скажите, что вы что-то пушили** — я подтяну
изменения. И наоборот: если я только что сообщил о пуше, сделайте
`git pull` (в github.dev — перезагрузите вкладку) до правок.

Конфликт не смертелен, но разбирать его дольше, чем предупредить.

## Если не пускает в админку

Симптом: `/admin/login` не принимает пароль, или пускает, но всё
пусто и разделы недоступны.

Вход устроен из двух частей, и ломаются они по отдельности:

1. **пользователь в Supabase Auth** — он же пароль;
2. **строка в `public.admin_users`** — она и даёт права. Внешнего
   ключа между ними нет намеренно, поэтому удалённый пользователь
   оставляет за собой осиротевшую строку.

**Сменить пароль** — Authentication → Users → строка с почтой →
поле пароля. Или из SQL Editor:

```sql
update auth.users
set encrypted_password = extensions.crypt('новый-пароль', extensions.gen_salt('bf')),
    updated_at = now()
where lower(email) = lower('ваша@почта');
```

**Если пользователя нет вовсе** (Authentication → Users пуст):
Add user → Create new user, обязательно с **Auto Confirm User**,
затем привязать права к новому идентификатору:

```sql
update public.admin_users a
set user_id = u.id
from auth.users u
where lower(u.email) = lower(a.email);
```

**Проверить, что всё сошлось:**

```sql
select a.email, a.user_id = u.id as linked
from public.admin_users a
left join auth.users u on lower(u.email) = lower(a.email);
```

`linked = true` — можно входить. `linked` пустой означает, что
пользователя с такой почтой в Auth нет.

Восстановление пароля по почте не работает и работать не будет:
страницы, которая принимает токен из письма, в приложении нет, а
Site URL проекта до сих пор указывает на `localhost`. Для одного
организатора это не проблема — пароль задаётся напрямую.

## Письмо со ссылкой на localhost

Supabase → Authentication → URL Configuration → **Site URL**. Там
всё ещё `http://localhost:3000`, отсюда и адрес в письмах. На вход
это не влияет — админ входит по паролю, без переходов по ссылкам, —
но до запуска поставьте туда боевой адрес.
