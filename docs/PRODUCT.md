# Продукт

## Задача

Организатор городского фото-квеста не должен весь вечер принимать
фотографии в мессенджере, вручную вспоминать, чья это команда,
искать нужное задание, вести таблицу баллов и переписывать
рейтинг.

Приложение забирает эту работу: команды отправляют фотографии
сами, простое проверяется автоматически, организатору остаются
только спорные случаи.

## Мероприятие

|          |                                               |
| -------- | --------------------------------------------- |
| Название | Движ-Патруль                                  |
| Формат   | Городской фото-квест                          |
| Город    | Leipzig, Германия                             |
| Дата     | 15.08.2026, старт 15:00 (Europe/Berlin)       |
| Участие  | 15 € с человека                               |
| Команды  | до 10, по 4 человека — максимум 40 участников |
| Задания  | 30–50, выполняются в любом порядке            |
| После    | BBQ, разбор кадров, награждение               |

Маршрута нет: команда сама решает, какие задания брать и в каком
порядке. Каждое засчитывается один раз, число попыток задаётся
отдельно для каждого задания.

## Участник

1. Открывает сайт на телефоне.
2. Создаёт команду или входит по коду от капитана.
3. В момент старта видит список заданий.
4. Открывает задание, читает условие и критерии.
5. Снимает или выбирает фотографию.
6. Отправляет — **и сразу идёт дальше**, не дожидаясь проверки.
7. Позже видит результат и начисленные баллы.
8. Следит за прогрессом команды и местом в рейтинге.

Шестой пункт — ключевой. Всё приложение построено вокруг того,
что участник не стоит на месте в ожидании ответа.

Регистрация email и пароля не требует: на один вечер заводить
учётную запись бессмысленно.

## Организатор

- Заводит мероприятие, открывает и закрывает регистрацию.
- Ставит лимит команд от 1 до 10.
- Импортирует 30–50 заданий файлом, правит критерии.
- Запускает, приостанавливает и завершает квест.
- Видит команды, участников и отправки по мере поступления.
- Проверяет вручную **только спорное**.
- Принимает, отклоняет, меняет баллы, начисляет бонусы и штрафы.
- Управляет рейтингом: показать, скрыть, заморозить.
- Выгружает результаты и фотографии.
- Перезапускает зависшие проверки.

## Роли

| Роль        | Что видит                                |
| ----------- | ---------------------------------------- |
| Посетитель  | Главную, правила, публичный рейтинг      |
| Участник    | Задания, свои отправки, прогресс команды |
| Капитан     | То же плюс состав команды до старта      |
| Организатор | Всё, включая журнал действий             |

Участник не видит фотографии других команд — ни в интерфейсе, ни
по прямой ссылке.

## Принципы

**Мероприятие важнее технологий.** Если откажет автоматическая
проверка, кончится квота или пропадёт связь — квест продолжается.
Фотографии сохраняются, статусы уходят в ручную проверку,
организатор подтверждает баллы сам.

**Участник не ждёт.** Загрузка занимает секунды, проверка идёт
фоном.

**Улица, а не офис.** Одна рука, солнце в экран, дрожащий
мобильный интернет. Отсюда крупные зоны нажатия, сжатие
фотографий в браузере, черновики в IndexedDB и отсутствие
лишних запросов.

**Результат должен быть объясним.** Баллы — журнал транзакций, а
не счётчик. Действия организатора пишутся в аудит. Через месяц
можно восстановить, почему у команды именно столько очков.

**Следующий квест — без программиста.** Дата, город, задания,
лимиты и правила лежат в базе. Новое мероприятие заводится
через админку.

## Границы MVP

Не входит намеренно: онлайн-оплата, чат, профили участников,
постоянный GPS-трекинг, интерактивная карта, нативные
приложения, достижения, реферальные программы, мультиарендность.

Масштаб фиксирован: одно мероприятие, 10 команд, 40 участников,
50 заданий, 500 фотографий. Архитектура рассчитана на верхнюю
границу, а не на «обычно будет меньше».
