# Студия

Внутреннее рабочее место команды DVIZH: `/studio`. Живёт в этом же
приложении и в той же базе, что и игра: заявка → проект → событие
строятся поверх одних таблиц, а шаблоны игр запускаются на этом же
движке. Лендинг (`dvizh-events-os`) — витрина: он только пишет
заявки в таблицу `leads`.

## Разделы

| Раздел | Кому | Что |
|---|---|---|
| Заявки `/studio/leads` | владелец, менеджер | воронка, бриф, связь, статус, ответственный, заметки |
| Команда `/studio/team` | владелец | приглашение, роли, доступ, ссылка для входа |
| Игра `/admin` | все роли | админка мероприятия, как раньше |

Дальше по плану: проекты (выигранная заявка → проект), шаблоны игр
с тестовым режимом и брендом клиента.

## Роли

Хранятся в `admin_users.role` (миграция `0036_staff_roles.sql`).

- **owner** — владелец: всё, включая состав команды.
- **manager** — менеджер: заявки, проекты и игра.
- **host** — ведущий: только игра.

Отключённый сотрудник (`disabled_at`) теряет доступ на следующем же
запросе. Строка не удаляется — на неё ссылаются заявки и журнал.
Последнего владельца нельзя ни понизить, ни отключить: это
проверяет триггер в базе.

## Вход

1. **Пароль** — как раньше.
2. **Ссылка от владельца.** «Команда» → «Ссылка для входа» или
   приглашение нового человека. Одноразовая, живёт около часа,
   пересылается в Telegram. Не зависит от настроек почты Supabase.
3. **Ссылка на почту** — на странице входа. Письмо шлёт Supabase,
   поэтому нужны две настройки в Supabase → Authentication →
   URL Configuration:
   - Site URL: `https://dvizh-patrol.vercel.app`;
   - Redirect URLs: `https://dvizh-patrol.vercel.app/auth/confirm`.

   Ссылку из письма нужно открыть в том же браузере, где её
   запросили. Встроенная почта Supabase отправляет несколько писем
   в час — для команды из нескольких человек хватает.

Все ссылки приходят на `/auth/confirm`: он впускает только
действующих сотрудников, остальных разлогинивает.

## Заявки с сайта

Лендинг пишет в `leads` публичным ключом этого проекта. RLS
разрешает ему только вставку новой заявки с `source = 'site'`.
id заявки генерирует сайт, чтобы прислать в Telegram ссылку на
карточку (`STUDIO_URL` в env лендинга).
