# App Preview · 24 секунды

Вертикальный ролик о том, что происходит после входа по коду:
рука карточек, переворот, задание, карта, фотография, проверка,
баллы, рейтинг.

**Готовый файл:** [`output/dvizh-patrol-app-preview.mp4`](output/dvizh-patrol-app-preview.mp4)
— 1080×1920, 30 fps, H.264 High / yuv420p, AAC LC 48 кГц стерео,
ровно 24,000 с.
**Контрольный лист кадров:** [`output/contact-sheet.jpg`](output/contact-sheet.jpg).

Раскадровка с точным таймингом — [`storyboard.md`](storyboard.md).

---

## Главное правило

**Всё игровое в кадре — настоящее приложение.** Ни один экран не
нарисован: Playwright ведёт живой сценарий по настоящему DOM,
статусы приходят с сервера, баллы считает та же серверная функция
`accept_submission`, что и на мероприятии. Нарисованы только
заставка, финальная плашка и подписи — и они честно называются
титрами.

Приложение под ролик не переписывалось. Единственная правка в
`app/` — `.leaflet-container` получил тёмный фон (см. «Что
изменилось в приложении»), и это исправление живой ошибки, а не
косметика для съёмки.

## Как это устроено

### Почему стенд, а не боевой проект

Боевое мероприятие стоит в статусе «Завершён»: обычный вход
заблокирован, и участник увидел бы «мероприятие завершено» —
ровно то, чего в ролике быть не должно. Менять статус боевого
события ради съёмки нельзя.

Поэтому запись идёт на локальной копии: настоящая схема из
`supabase/migrations`, настоящий пул заданий из
`data/tasks-leipzig-2026.json`, настоящие фотографии Лейпцига из
`public/assets` — и вымышленные команды. Боевая база при записи не
читается и не меняется.

### Из чего собран стенд

| Слой           | Чем закрыт                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| Postgres       | Локальный кластер, `scripts/local-db.sh` + `supabase/local/00-supabase-shim.sql`                           |
| PostgREST      | Настоящий бинарник PostgREST 12 поверх этой базы                                                           |
| Auth + Storage | `stack/supabase-shim.mjs` — минимальный GoTrue (пароль → JWT) и файловое хранилище с подписанными ссылками |

Приложение об этом не знает: для него это обычный Supabase по
адресу из `NEXT_PUBLIC_SUPABASE_URL`.

Так вышло не от хорошей жизни: сеть песочницы, где собирался
ролик, пускает наружу только реестры пакетов, GitHub и Google
Fonts. Ни `*.supabase.co`, ни реестры контейнеров оттуда
недоступны, поэтому ни боевой проект, ни `supabase start` не
поднимаются. На машине с обычным интернетом стенд не нужен:
достаточно указать в `.env.local` тестовый проект Supabase и
пропустить `stack/start.sh`.

### Как снимается экран

Chromium запускается под Xvfb с `--force-device-scale-factor=3`, а
поверх ставится эмуляция устройства **390×844 с тач-вводом**.
Внутри страницы `innerWidth` равен 390, `devicePixelRatio` — трём:
ровно то, что видит iPhone. На экране X это 1170×2532 настоящих
пикселей, и кадр уходит в 1080×1920 с уменьшением, а не с
растяжением.

Кадры снимает `ffmpeg -f x11grab`, а не встроенная запись
Playwright: та пишет вьюпорт в CSS-пикселях (390×844), а CDP-скринкаст
отдаёт кадры размером с композиторскую поверхность — тоже 390×844.
`x11grab` берёт то, что реально нарисовано, со всеми CSS-переходами
и настоящим 3D-переворотом карточки.

Область захвата не задана числом, а вычисляется: перед записью
страница заливается контрольным цветом, кадр разбирается
попиксельно, и дальше пишется ровно прямоугольник страницы без
панели вкладок.

## Что нужно на машине

- Node 20+ и зависимости проекта (`npm ci`);
- PostgreSQL 16 (клиент и сервер), путь к бинарникам — `PG_BIN`;
- `ffmpeg` и `ffprobe`;
- `Xvfb`;
- Chromium (Playwright или свой — `PLAYWRIGHT_CHROMIUM_PATH`);
- бинарник PostgREST 12 в `video-preview/scratch/bin/postgrest`.

Переменные — в [`.env.example`](.env.example). Секретов там нет и
быть не должно: стенд обходится тестовыми ключами.

## Команды

Всё из корня репозитория.

```bash
npm run video:deps      # шрифты Unbounded/Onest в assets/fonts
npm run video:stack     # Postgres + PostgREST + shim + демо-данные + приложение
npm run video:seed      # только пересобрать демо-данные
npm run video:capture   # записать сцены приложения (Xvfb + Playwright)
npm run video:titles    # записать заставку и финальную плашку
npm run video:overlays  # отрисовать подписи в PNG
npm run video:audio     # синтезировать музыку и эффекты
npm run video:render    # смонтировать MP4
npm run video:verify    # ffprobe-проверка + контрольный лист
npm run video:clean     # удалить временные демо-данные и остановить стенд

npm run video:build     # всё перечисленное по порядку, одной командой
```

`npm run video:build` пересобирает ролик от пустой базы до готового
файла. На ноутбуке это примерно пятнадцать минут, из них половина —
запись сцен в реальном времени.

Переснять одну сцену, не трогая остальные:

```bash
SCENES=map npm run video:capture
npm run video:render
```

Сценарий при этом проходится целиком — иначе состояние базы
разъедется с тем, что показывают соседние сцены.

## Демо-сценарий

Мероприятие: `leipzig-2026`, статус «Идёт», дата настоящая —
**05.09.2026, 14:00, Leipzig, 15 € с человека**. Срок окончания не
задан: по схеме это «закрывает только организатор».

Пул — все 45 заданий из `data/tasks-leipzig-2026.json`: 17 активов,
16 загадок, 12 фото-повторов.

Шесть вымышленных команд. Записываем «Движ-Демо», код `DEMO26`,
участники Кирилл, Настя, Тимур; в кадре к ним присоединяется Аня.
До съёмки у команды 450 баллов и второе место, у лидера 530.

В руке шесть карточек: №22 «Место с открытки» (фото, 160),
№4 «Тот, кто вписал город в свою книгу» (загадка, 120),
№46 «Русалки у фонтана», №47 «Подарок городу»,
№41 «Лейпциг одним кадром», №1 «Патруль с патрулём».

Команда выполняет №22: отправляет снимок Augustusplatz,
организатор принимает, начисляется 160 баллов, счёт становится 610
и команда выходит на первое место. Все цифры в подписях — из базы.

Фотографии: эталоны и demo-снимок сделаны из `public/assets` —
это городские кадры Лейпцига, которые уже стоят на боевом

## Что изменилось в приложении

Одна строка в `app/globals.css`:

```css
.leaflet-container.leaflet-container {
  background: var(--color-canvas-deep);
}
```

Компоненты карты и раньше просили тёмный фон утилитой
`[&_.leaflet-container]:bg-canvas-deep`, но она не срабатывала:
утилиты Tailwind лежат в `@layer`, а `leaflet.css` подключается без
слоя и выигрывает у них при любой специфичности. На тёмном экране
из-за этого вспыхивал светлый прямоугольник `#ddd`, пока летят
тайлы, — и оставался насовсем, если тайлы не пришли. Правило вне
слоя и с удвоенным классом бьёт `leaflet.css` специфичностью, без
`!important`.

Это исправление живой ошибки, а не подгонка под съёмку: то же
самое видел бы участник на городском интернете.

## Известные ограничения

**На карте нет тайлов подложки.** Сеть песочницы блокирует все
источники карт — `tile.openstreetmap.org`, CARTO, Stadia, Mapbox,
Wikimedia. Приложение честно рисует то, что умеет само: границу
игрового поля, обведённые районы, кресты меток и радиусы зачёта на
холсте системы. С обычным интернетом та же сцена идёт с тёмной
подложкой OSM (или Mapbox, если задан `NEXT_PUBLIC_MAPBOX_TOKEN`).
Подделывать карту рисованной картинкой не стали.

**Рейтинг меняется склейкой, а не анимацией.** Приложение не
анимирует перестановку строк: страница рейтинга серверная и
приходит уже отсортированной. В ролике переход показан монтажной
склейкой «было / стало» — обе половины сняты с настоящего экрана.

**Золотое задание есть только в витрине лендинга.** В руке команды
его нет — так устроен пул. Витрина снята отдельной сценой
(`landing-deck`) и в финальный монтаж не вошла: на неё не осталось
времени в 24 секундах.
