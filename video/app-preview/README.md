# App Preview · Движ-Патруль

Вертикальный продуктовый ролик для Instagram Reels: 1080×1920,
30 к/с, 43,5 секунды. Показывает игровой цикл целиком — код,
команда, рука карточек, задание, карта, город, отправка, проверка,
баллы, история места, рейтинг, архив.

Проект изолирован: свой `package.json`, свои зависимости, своя
папка `node_modules`. Приложение он не трогает и в его сборку не
попадает.

## Команды

```bash
cd video/app-preview
npm install

npm run preview   # студия Remotion в браузере
npm run render    # полный ролик, 43,5 с
npm run teaser    # тизер, 15 с
npm run cover     # обложка PNG
```

Рендер требует Chromium в режиме headless shell. В этом окружении
путь прописан в скриптах через `--browser-executable`; на другой
машине флаг можно убрать — Remotion скачает свой браузер.

## Как устроен показ интерфейса

Три уровня, все три — в `src/parts.jsx`.

**`Phone`** — телефон целиком, приложение как предмет. Появление
продукта.

**`Screen`** — настоящий экран во всю безопасную зону, ничего не
обрезано: видны и шапка, и нижняя навигация. Геометрия задана
одним объектом `SCREEN` в `theme.js`.

**`Zoom`** — наезд камеры на место внутри того же экрана. Экран не
режется и не подменяется вырезкой: он остаётся целым и виден
вокруг, лишнее уходит в тень. Поэтому зритель всё время понимает,
где в приложении находится показанное.

`Mark` рисует рамку на элементе. Координаты — прямоугольник
`[x, y, ширина, высота]` в пикселях исходника 1170×2532. Если
экран в этот момент масштабируется, тот же `scale` надо передать и
в `Mark`, иначе рамка съедет.

## Пересъёмка экранов

Экраны сняты настоящим браузером на мобильном вьюпорте 390×844 при
плотности 3 — то есть 1170×2532 пикселя.

1. поднять стенд: `./scripts/local-db.sh start`, `npm run db:qa`,
   затем `node scripts/qa-rest.mjs` и `npm run start` в корне;
2. войти тестовой командой и снять нужные экраны Playwright'ом в
   `video/app-preview/assets/screens/` с тем же вьюпортом;
3. имя файла — ключ, по которому сцена его находит.

Координаты для `Mark` и `Zoom` снимаются с самого снимка, а не на
глаз: `getBoundingClientRect()` элемента, умноженный на три.
Ошибка в десяток пикселей видна как съехавшая рамка.

## Данные мероприятия

Дата, время, город, цена и состав команды в финале взяты из базы:

```sql
select starts_at, city, price_cents / 100, team_size from public.events;
```

На 27.08.2026 это 05.09.2026, 14:00, Leipzig, 15 €, до 5 человек.
Перед перерендером стоит сверить их ещё раз.

## Звук

Ролик отрендерен **без музыки и без звуковых эффектов**: взять или
синтезировать аудио в этом окружении нечем. Значит, мастер и есть
чистая версия — отдельный файл `…-clean.mp4` был бы его точной
копией, и в репозитории его нет намеренно. Чистой версией станет
нынешний мастер, как только в новый ляжет звук.

Когда трек появится:

```bash
cp renders/dvizh-patrol-apple-style-reels-1080x1920.mp4 \
   renders/dvizh-patrol-apple-style-reels-clean.mp4

ffmpeg -i renders/dvizh-patrol-apple-style-reels-clean.mp4 \
       -i audio/track.mp3 \
       -map 0:v -map 1:a -c:v copy -shortest \
       renders/dvizh-patrol-apple-style-reels-1080x1920.mp4
```

Либо через саму композицию — тогда звук встанет по кадрам:
положить файл в `assets/audio/`, добавить `<Audio src={staticFile(
'audio/track.mp3')} />` в `Preview.jsx` и перерендерить. Второй
способ лучше: акценты сводятся с монтажом кадр в кадр.
